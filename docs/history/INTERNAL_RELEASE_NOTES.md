- Material warnings at print start (#1336). Owner ruling, restated 2026-11-11 (first recorded with #1190 and #1213): no filament or material condition hard-blocks a print. **Release Date:** Unreleased until tagged. Set when the tag is cut.
**Note on 2.2.8:** the 2.2.8 tag sits on a test-release commit that is not on main, and main's `__version__` stayed "2.2.7". 2.2.9 is the release that follows 2.2.7; its range is 2.2.7..main.
**Owner rulings recorded in this range:** no filament condition hard-blocks a print; filament problems warn and the operator can accept them (PRs #1190, #1213). The first-run setup gate is reversed on purpose: an install with no credential serves the Web UI openly (PR #1116).
**Still owed (owner-deferred):** the owner released 2.2.9 without the AD5X "Release 2.2.9 live checks" and the older owed live checks; every one stays tracked on #1082 (real-printer runs of the filament warn-and-accept and fallback rounds, reprint start verdicts, alert buttons and `/print-stop`, the stock-firmware bay selection from PR #1221, real-camera passes for the camera watch changes, live chat-platform runs of the delivery fixes and per-session web chat, the README quickstart on a real clean host, GPU encode and inference, the Discord Activity sitting, the #1103 live check and Pages enablement). The deferral is recorded on the release checklist #1197.

- The in-repo Unraid template (`docker/unraid/print-handy.xml`) takes the same install-surface slimming the Community Applications template received: from ninety-odd fields to eight — the Web UI port, a single **Appdata** path mounting all of `/data` (the separate state/archive/records/cache/Spoolman-data/account-tokens mappings and the legacy `/data/hermes` path fold into it; the host folders under appdata are unchanged, so an existing install's data layout already matches), the **Timelapse Archive** path (default inside Appdata), the bundled/external Spoolman URL choice (kept, now shown in Advanced View), the container timezone and the GPU passthrough entries (the `/dev/dri` device entry — new to this file, mirroring the CA template — and both NVIDIA variables, now in Advanced View instead of hidden). Every removed setting stays settable in the mounted config file or the Web UI, and every secret through the profile `.env` inside the Appdata path or a variable added by hand. The metadata differences from the CA file (digest-pinned `Repository`, GitHub support link, no Branch/TemplateURL/Icon) stay: this file is the release reference, not the listing. The Orca bump flow no longer records the bundled Orca version in this file (the channel field is gone), and DOCKER.md's template-shaped passages (the Spoolman LAN opt-in, account tokens, the GPU steps, the state-volume rename) describe the slimmed surface. Existing installs are untouched: Unraid keeps a created container's saved paths and variables until the operator edits them.
- The Hermes install method and the `bot.mode: hermes` runtime mode are removed, clean break. `scripts/install-hermes.sh`, the top-level `hermes/` payload (profile templates, skills, systemd units), the Hermes plugin manifest and the plugin-owned clarify renderer (`print_handy/hermes/clarify_ui.py`) are deleted; the setup wizard and guided setup no longer offer a mode choice. The bot is the only runtime: its own prompt registry is the one question path, design resolves only its `[design]`/`[llm]` HTTP endpoint (the `ctx.llm` fallback is gone), and the handler module's agent-only hooks (receipt, stray-chat claim, tool-call guards) are deleted with the host that ran them. A config that still states `bot.mode: hermes` is refused at load with a named message telling the operator the install/mode was removed and to run the standalone bot or the Docker image; the removed `paths.hermes_bin` / `paths.hermes_agent` / `paths.hermes_restart_helper` keys and the `discord.clarify_ui` setting are gone from the schema. Not renamed here: the `print_handy/hermes/` package name, the plugin's location and `paths.hermes_home` are renamed in the follow-on PRs of the broader cleanup plan (this PR is its dead-code removal step); the `/data/hermes` legacy volume fallback (#914) still applies, and the generic `[llm]`/`[agent]` endpoint lanes stay (an endpoint that happens to be a Hermes agent API is still just an endpoint). Standalone behavior is unchanged: same handlers, same bot-drawn questions, same bot check rows except the ones that described the Hermes install.
- The in-container timelapse capture knobs join the Web UI settings catalog: `timelapse.capture_trigger` (a picker carrying exactly the settings choice set: interval, layer, both), `timelapse.capture_interval_s`, `timelapse.capture_max_frames` and `timelapse.capture_max_bytes` are now editable on the /config page's Timelapse group and written to the settings file through the same validated write-back as every other field, so the four matching Unraid template variables can be removed — the settings live in the config file like everything else. The four variables leave the #657 cross-surface contract's exemption list (the ratchet only shrinks); `timelapse.capture_encoder` keeps its exemption. The capture loop already read all four from the loaded settings, so no runtime behavior changes.
- The bundled OrcaSlicer moves from v2.5.0-rc to the v2.5.0 final (upstream published 2026-11-07; tag commit `40ecc66f78ed72dc368e0c1ebe40d77f00cc8a19`; amd64 `d13eb0a9…`, aarch64 `00a4fa0a…`; the CI flatpak bundle pin moves with it). - Watchdog verdict source (#455): new `vision.watch_source` setting (`auto` / `endpoint` / `local`, default `auto`) on every surface. `auto` keeps the existing route precedence for the camera watchdog's verdicts; `endpoint` pins the watch to the endpoint routes and never consults the local failure detector (not even as the early-layer fallback); `local` pins the watch to the local detector — frames are judged on this machine even when a vision endpoint is configured for label reads — and counts as enabling the detector for the watch, so `vision.local_detector_enabled` does not also have to be on. Label reads and roasts never follow the setting.
- AI fix sealing caution (#978 follow-up): when a mesh repair fills damage holes, the fix confirmation now carries a plain caution — the repair seals that many openings, and a part meant to have openings (a tube, a vent, holes) should be checked against the preview and not applied. The caution is built by `ai_fix.repair_warnings` and rendered through the shared `ai_fix.fix_lines`, so it reaches both flows that offer a fix (the post-slice intake gates and the chat repair flow) before the operator confirms, and it appears only when the repair actually filled holes (`holes_filled` > 0): a repair that fills nothing shows no caution, and designed openings keep their existing per-opening listing and the "Apply, but keep the openings open" choice. Offline coverage: `tests/test_ai_fix_followups_978.py` pins the caution and its absence at the helper, at the shared confirmation renderer, and in the chat flow's confirmation question (a damage-holed model warns; the open-top designed-opening fixture does not).
- Declared part roles, assembly transforms and collisions (#1017, item 3): a `project_v1` component may now declare its `role` (`structural`, `coupon`, `reference`, or `rack_ear`) and its `assembly_transform` placement (`translate_mm` plus `rotate_deg`, degrees about X, then Y, then Z), validated in `core/projects.py` when the manifest is built — an invalid declaration fails the build instead of being dropped, and undeclared components are unchanged. `core/assembly_check.py` consumes the declarations (via `review(..., project=manifest)` or a direct `declarations` map): a declared role beats the file-name inference and is labeled `declared` in the project-shape evidence while inference stays the labeled fallback; a declared `rack_ear` earns the EIA-310 panel-clearance check by declaration rather than by the height heuristic, a declared non-ear is no longer ear-checked by that heuristic, and a declared ear reviewed with no rack size is a warning rather than a silent pass. Placed parts are reported with their placed bounds and checked pairwise for collisions — disjoint placed bounds prove no collision, overlapping bounds get an exact interpenetration test (a vertex strictly inside the other solid, or an edge piercing a face with its interior inside it), and flush contact is not a collision. Parts without a declared placement are named in a partial-placement warning, and a review with no placed parts still states transforms and collisions as not checked. Still not wired into a caller: design sessions remain single-part on main, so the manifest is the declaration surface and `review` is the seam a multi-part session or the AI design handoff calls.

## 2. Multi-Plate Capacity Evaluation & Bounding Box Decoupling

### Problem Statement
- In prior versions, `orca_adapter.py:orca_plate_capacity` blindly returned `1` for any multi-plate 3MF file to avoid false negative zero-capacity reports.
- Meanwhile, `verified_scale_choices` evaluated model dimensions by extracting `source_triangles` across the entire 3MF file. In multi-plate Bambu/Orca projects, plates are placed side-by-side in global coordinate space. For the 4-plate Strandbeest, this produced a global bounding box of **501 x 529 mm**, causing `verified_scale_choices` to conclude the model required scaling to `<= 0.41`.

### Implementation Details
- **`_multi_plate_capacity(source, state, scale, single_margin)`**:
  - Inspects `plate_manifest(source)` to extract individual plate object assignments.
  - Uses `color_geometry._world_bounds(archive, object_ids)` to compute the bounding box of each plate independently.
  - Compares each plate's scaled dimensions `(dx, dy, dz)` against usable bed boundaries (`eff_w = bed[0] - 2 * margin`, `eff_d = bed[1] - 2 * margin`, `max_h`).
  - Supports 90-degree bed rotation (`fits = (dx <= eff_w and dy <= eff_d) or (dy <= eff_w and dx <= eff_d)`).
  - Returns `0` if any plate exceeds usable dimensions; returns `1` only if all plates fit.
- **`verified_scale_choices(source, state)`**:
  - Multi-plate 3MF files bypass whole-canvas `source_triangles` extraction.
  - If capacity at 1.0 is `> 0`, returns `[1.0]`.
  - If capacity at 0.5 is `< 1`, returns `[]`.
  - Runs an integer binary search `low, high = 50, 99` over `orca_plate_capacity(..., scale=middle / 100.0)` to find the maximal scale where all plates fit.
  - Returns `_scale_ladder(best_scale)` (for Strandbeest, Plate 3 circular fan at 231 mm yields best scale `0.94`, returning `[0.94, 0.75, 0.5]`).
