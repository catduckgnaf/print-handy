# Documentation audit, 15 November 2026

Scope: `catduckgnaf/print-handy` at base commit `595ef054ddd0b333a28071e354bf26e298e0e2d4`. This is the editorial review behind the friendlier README and documentation-navigation changes. It is not a claim that all supported printers have passed live hardware tests.

## Inventory and method

The repository tree contains **86 entries in 15 `print_handy/data/printers-registry/*.toml` files** (counting `[[printer]]` blocks, including generic entries). The old README's fixed claim of 84 models had drifted. The replacement deliberately doesn't promise a number that will go stale on the next profile PR. See `tests/test_knowledge.py` for registry/code parity and `docs/PRINTER-SUPPORT.md` for what each support level proves.

Reviewed `README.md`, `docs/README.md`, the printer guides, installation guides, Web UI, design/editing, status voice, firmware, Docker settings and license provenance. The repository-wide path pass inspected **76 Markdown files** (58 active README / contributing / guide files and 18 `docs/history/` records) and **685 Markdown link occurrences**. Relative file targets resolved to repository entries. Four apparent misses in the simple parser were not missing documents: `URL` is a placeholder twice in a fenced release-note example, and two links intentionally target directories (`.github/ISSUE_TEMPLATE` and `assets/branding/`).

**Post-edit check:** The ten changed/new Markdown files contained **298 Markdown link occurrences**. Their relative targets all exist in the branch tree, and **30 referenced heading fragments** were compared against actual heading text in the destination files; those 30 resolved.

**Limit of the broader link pass:** It checked exact relative paths using the tree, not every external HTTP endpoint, every fragment anchor elsewhere in the repository, or JavaScript-rendered link. Selected important upstream links were opened separately; `https://zmod.link` redirects to its wiki, the OpenCreator and Reforge GitHub repositories resolve, and the Unraid / Home Assistant repositories were read through GitHub. The docs site and Discord invite could not be independently checked through the available public link fetcher. Do not mistake this for a universal live-link guarantee.

## Findings and changes

Every job waits for a human.` and the repeated approval caption from `README.md`. Kept actual start and access instructions where they matter, including `docs/DOCKER.md` and `docs/WEBUI.md`. |

The Unraid repo is `catduckgnaf/catduck-unraid-templates`; the add-on repo is `catduckgnaf/print-handy-haos-addon`. |

The README now says **can flag** problems, not that every printer is watched. |

| Licensing text was confusing. | Current `LICENSE` is **AGPL-3.0-only**, as is `pyproject.toml`. The `2.2.7` tag's `LICENSE` actually contains MIT text, and the current `NOTICE` preserves that historic legal provenance. ## Verification boundaries and intentionally untouched surfaces

- **FlashForge stock AD5X:** `docs/FLASHFORGE-STOCK.md` says LAN upload/start is implemented but its request behavior has not been verified on a real stock AD5X. Do not promote it to hardware-verified.
- **ZMod:** `docs/ZMOD.md` and `docs/DEVICE-AD5X.md` distinguish a limited physical AD5X baseline from a confirmed Print Handy-started print. Do not conflate them.
- **OpenCreator:** `docs/OPENCREATOR.md` calls its Creator profiles documentation/config-verified **without** a live printer session. It also identifies upstream public-alpha status.
- **Reforge:** no dedicated `print_handy/printers/` vendor profile or registry entry in this audited tree. No compatibility assumption has been added.
- **Bambu A1:** `docs/BAMBU-A1-DOCKER.md` records a 2026-10-26 sliced/uploaded/started printer-reported run, which is more substantial than a mocked adapter test; it remains a specific report, not blanket Bambu verification.
- **Release numbering:** `2.3.4` references and release-publishing questions were deliberately **not edited** in this documentation PR, per owner direction. The Docker guide has an older illustrative digest and tag under `#pinning-the-image`; operators should inspect the digest of the image they actually choose rather than copying historical digest text.
- **Historical content:** no edits to `NOTICE`, `LICENSE`, `docs/history/`, code, container images, CI workflows or an unrelated documentation-site repository. The public docs site is maintained separately at `catduckgnaf/print-handy-docs` and needs its normal sync process after these source changes merge.

## Checks still worth doing

A CI link checker that understands GitHub heading anchors, fenced code samples, redirects and external HTTP responses would close the remaining link-audit gap. A release-time comparison of README install snippets against the published Compose/tag/digest would prevent stale installation examples. Above all, more real-printer reports matter more than a bigger test-count boast. A passing fake Moonraker is still a fake Moonraker.
