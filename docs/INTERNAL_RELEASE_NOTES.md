# Print Handy Internal Release Notes

# Unreleased

- Web UI printer control API (#708): `POST /api/printers/<id>/pause`, `/resume`, `/cancel` and `/target` (target temperatures), behind the new `webui.controls_enabled` setting (`PRINT_HANDY__WEBUI__CONTROLS_ENABLED`, default `false`). While the setting is off the routes are not served at all; while on, the existing Web UI access token is required. Actions act on the one named printer through its own transport (every connection family; targets on Moonraker and OctoPrint printers, a named refusal elsewhere); chat control stays confirm-first and emergency stop stays chat-side. This is the API the Home Assistant integration's phase 3 builds against.
- Web UI auth opt-out: `webui.require_auth` (`PRINT_HANDY__WEBUI__REQUIRE_AUTH`, default `true`). Set `false` on a trusted network and the Web UI starts on a LAN bind with no access token and no login; a token left set is ignored. The Docker gate logs `authentication OFF` at start. Not editable from the Web UI itself.
- One "Print started" post per start: the start claim and recorded start message now match the printer's 3MF unpack path (`3mf_print/X.gcode`), so the listener edits the intake's post instead of posting a second one.
- "Preparing to start" shows the nozzle and bed targets read from the uploaded G-code.
- One "Print complete" post per print: the complete -> standby announcer pass no longer re-drives a timelapse render that is still running in the same process (it rendered twice and posted once without the video). A pending video after a real listener restart is still re-driven.
- Corrupt timelapse fix: captured-frame renders now write to a unique temp file, take a per job render lock, and must fully decode before they are cached or attached; a cached video that no longer decodes is re-rendered. Overlapping renders used to share one fixed `.partial.mp4`, and the loser rewrote the winner's renamed file into a video with no streams (black in VLC, blocky in Discord).
- A bare printer record holding the seeded family default (PLA 210/60) no longer overrides a variant spool's temperature (Silk PLA slices at 220 °C).

# Version 2.2.3

**Release Date:** 2026-10-31
**Still owed:** the Snapmaker U1 is unverified on live hardware (no U1 available); the 2.2.2 live checks (first chat print on a screenless ZMod AD5X, live-stream transcode, Sovol/MQTT/exclude-object/next-plate on hardware) remain owed.

- Starts confirmed, not assumed (#688, #691, #693, #698): a screenless (Helix) AD5X start that took longer than 30 seconds to warm up is no longer reported as "Didn't start"; it shows as started, warming up, or "sent, not confirmed yet", and Print Handy never resends. An unconfirmed start clears by itself once the printer reports that exact file. Problems found before anything is sent (a slot check, a failed upload) say the print did not start instead of "Start sent". OctoPrint, PrusaLink, Elegoo and stock Flashforge starts are confirmed over a short window; a printer that rejects a start (for example "Must home") is reported as refused with its message and is free for the next job; a lease left by a restarted container no longer blocks the printer after 15 minutes. Print again and multi-copy plates work on the AD5X mapped path.
- Start-path review fixes (#698): a live lease on this host is never taken over by a second job, and a launch that loses its lease stops before sending; after a rejected start only a readback naming this exact file may say started; the generic Klipper path keeps an unconfirmed start uncertain unless this file is positively failed or cancelled, and never queries ZMod objects; the outcome line stays compact and a cut-off line counts as pending; pre-submit failures release their announcement claim.
- Silk PLA and spool temperatures (#689, #690, #692, #697): material names with a space (Silk PLA) no longer fail with "malformed per-tool filament_type metadata"; the AD5X SILK slot label is accepted for Silk PLA; every slice and verify uses its own job spool's temperature (Silk PLA in an IFS slot prints at 220 °C, not 210 °C); multicolor PLA + Silk PLA on the AD5X slices each slot at its own temperature, and a job whose slots differ by more than 10 °C is refused. Slot mismatch messages name the slot and both values.
- Material profiles and vocabulary (#689, #697, #699): ABS, ASA, PETG, TPU, nylon and PC jobs no longer slice with PLA cooling and flow limits on non-Bambu printers; labels such as "Shiny Silk PLA", "PLA (Silk)", PA12, PET-CF, PCTG, TPU 95A, multi-color Silk and Wood/Glow/Metal PLA resolve; abrasive fills are refused on brass nozzles; PrusaLink, Elegoo and Snapmaker files with the wrong material, nozzle or temperatures are refused before they print; Spoolman temperatures of 0 no longer fail `set --spool`.
- Colors (#696): a mapped launch no longer refuses over the same color written differently (FFFFFF vs FAFAFA, 0C6283FF vs 0C6283); it warns on close or unreadable colors and refuses only on clearly different real colors. `#RGB`, `RRGGBBAA` and `0x` hex forms are accepted everywhere, a black AMS tray is recognized, and names such as "Dark Cyan" and "Burnt Orange" get matching preview colors.
- Screen-mode switches (#688): after switching between the native screen and screenless mode, slices use the active mode's bed mesh, a calibration mismatch names the mode that needs `/calibration`, and rebooting the printer no longer asks to confirm every loaded spool.
- "Preparing to start" no longer repeats the time estimate and slot list (#692).
- Replay tests built from recorded AD5X responses drive the real start and verify path (#695; tests only).
- Snapmaker U1 support: the U1 registers as a four-toolhead Moonraker (Klipper-fork) printer (`snapmaker.u1`, `multi_tool`, `filament_slots` stays 1 and `tool_count` is 4, the Prusa XL shape). Bed, height, temperatures and tool count are Snapmaker's published specification and are unverified; no live print has been run. Templates are generic files Print Handy wrote. The U1 joins the vendor-fork treatment for calibration and firmware updates (report-only guidance, never an apply), and the `PRINT_START`/`PRINT_END` macro pair its templates emit is scoped to it in the firmware registry.
- CI guards: Ruff (syntax and undefined names) runs on the whole Python tree, pip-audit checks both requirement files in a new `dependency-audit` job, and pytest-timeout fails a hung test (120 seconds per test, 600 for corpus cases).
- Prepared intake imports `plate_merge`, so the full-size split check no longer dies as a swallowed NameError.

# Version 2.2.2

**Release Date:** 2026-10-30
**Still owed:** the first live print from chat on a screenless ZMod AD5X (new in 2.2.0); the live-stream transcode against a live camera; the Sovol profiles, MQTT, exclude-object and the next-plate offer are offline-tested only.

**Upgrade notes (read before updating a 2.2.1 install):**
- Docker and docker-compose: the shipped default model is now `klipper.generic`, not `flashforge.ad5x` (#654, #663). An AD5X install that never set `PRINT_HANDY__PRINTER__MODEL` must set it to `flashforge.ad5x`, or it comes back as a one-slot Generic Klipper with the wrong start and end macros. The container now logs a warning when it sees an AD5X-shaped install running on the default, and the `filament_slots` error names the variable to set (#678). Unraid installs keep the model saved in their template.
- `timelapse.mode`, `services.camera_source` and the four `live_stream` values now take effect (#655). A value set in 2.2.1 that did nothing before changes behavior now: `timelapse.mode = "off"` stops capture and the rendered attach, `container` opens capture on its own, a camera pin is honored, and changing any live-stream value switches the live view to a transcoded stream.
- `printer.ifs_slots` is now `printer.filament_slots`; the old name still loads (details below).
- Generic Klipper and the SV06 allow 250 mm prints instead of 220 (#663).

**What users can do now:**
- Fuzzy matching hardening and widening (post-2.2.1 audit): the semantic-lookup client now validates what an endpoint returns (non-finite or non-numeric scores are rejected instead of crashing the lookup into "Lookup failed", scores clamp to 0–1, the 0.55 threshold is enforced client-side with duplicates dropped and a deterministic score order), reads under one total 10-second deadline with a 256 KiB body cap, and only accepts `http`/`https` URLs (with a cleartext warning for plain `http` to a non-local address). The local matcher now works fully offline on more of what people type: number words equal digits (`two`/`2`, `second`/`2nd`, `twenty one`/`21`, including inside titles like "Mark Two"), common variants fold together (plurals, `cfg`/`config`, `temp`/`temperature`, `mm`/`millimeter`, `hot end`/`hotend`), accents fold consistently and CJK text is no longer erased by the normalizer, and sound-spelled words (`enuf`, `retrakshun`) can reach their entries. A single confidence/conflict rule now governs every did-you-mean surface: a fuzzy result is used directly only at high confidence with a clear margin over the runner-up; a close or grey-zone result becomes a "Did you mean…?" pick-list instead (a mistyped command with several near matches now offers the choices rather than staying silent, and picking one runs it through the usual flow). Long stuffed titles no longer cost a quadratic scan in `/print-again` (the window pass is capped and its fuzzy scan covers the newest 500 archived prints; exact and substring matching still scan everything). The #468 boundaries are unchanged: exact matches behave exactly as before, print numbers stay exact (typing "two" never selects print #2), and a fuzzy hit can still only offer choices — never execute.
- Every Web UI setting now does what it says (the 2.2.1 settings-surface audit found six options that were offered and saved but changed nothing; all six are wired, none was removed):
  - **Camera source** (`services.camera_source`) pins the stills source for real: `moonraker` uses the Moonraker webcam snapshot only, `bambu` the printer's own Bambu camera, `go2rtc` the go2rtc fan-out only, and `none` turns camera images off — no watchdog stills, no timelapse capture, no fan-out. A path the pin excludes refuses and names the pin instead of silently using another source.
  - **Timelapse mode** (`timelapse.mode`) gates both timelapse paths: `off` stops in-container capture and the printer-rendered attach, `container` runs capture on its own and skips the rendered path, and `rendered` leaves the capture gate to the capture switch as before. The derived default gained a case for the same reason: with no Moonraker URL, an enabled capture now derives `container` instead of `off`, so the derivation cannot veto a capture the operator turned on. The **In-container capture** toggle (`timelapse.capture_enabled`) is offered in the Web UI next to the mode.
  - The **live feed values** (`live_stream.max_height`, `fps`, `max_bitrate_kbps`, `encoder`) shape the Discord live view: while all four hold their defaults the feed is the camera stream relayed as it arrives; changing any one makes go2rtc publish a transcoded live stream with all four applied (the ffmpeg argument builder's first production caller), fed from the loopback restream so the camera still gets one upstream pull. Timelapse capture and watchdog stills keep the camera's own stream. The `/print-live` text now says which of the two the feed is.
- Print events over ntfy (#622's second channel): set `notify.ntfy_enabled` and `notify.ntfy_url` (plus `notify.ntfy_topic`, or name the topic in the URL) to get the same events MQTT publishes as phone notifications. A protected topic's token is `NTFY_ACCESS_TOKEN` in the environment only. With both channels on, an event counts as delivered when either takes it, and one channel's failure never blocks the other or the chat post.
- Settings the Web UI was missing are now offered: the MQTT set (`notify.mqtt_enabled` / `mqtt_host` / `mqtt_port` / `mqtt_topic` / `mqtt_username`; the password stays `MQTT_PASSWORD` in the environment), **Printer serial** (`bambu.lan_serial`, shown with the Bambu LAN address the validator pairs it with), **Plate spacing** (`layout.spacing`), and the **Model endpoints** group (chat, design and agent endpoint URLs and model names; API keys stay in the environment). The `[notify]` section also joined the defaults tree, so it loads with its defaults like every other section instead of existing only when a file sets it.
- Macro registry coverage for every printer: the descriptive macro registry (`firmware/commands.toml`) previously described macros for only 3 of the 43 Moonraker models (AD5X, generic Klipper, Sovol SV06); every other Moonraker model's discovered macros listed as undescribed. Entries now cover the ZMod AD5M pair (shared `zmod_ff5x` base/client config set) and the Creator 5 pair's template-emitted names, PRINT_START/PRINT_END for every Sovol Klipper model, the SV08 stock `START_PRINT`/`CLEAN_NOZZLE` and the Zero's stock `START_PRINT`/`END_PRINT`, Creality's stock `START_PRINT`/`END_PRINT`, and Qidi's stock `PRINT_START`. Recorded NO-ADD verdicts (docs/MACROS.md): the Anycubic Kobra 2 and Elegoo Neptune families (fully inline profiles; a macro-led file is foreign on both), the Qidi end macro (inline), the Mainsail client set beyond the models verified to ship it, the SV08 stock end name (unverified), and the Creator 5 ZMod operator set beyond its template names. Also fixed: the Anycubic adapter's module docstring was a stale copy of the Creality one and described the wrong family's start code; it now matches the Anycubic guard and guide (fully inline start, no start macro).
- Web UI API: `GET /api/printers/<id>/status` serves one roster printer's live status as JSON (#664) — the roster identity fields plus the printer adapter's normalized status (`state`, `filename`, `progress`, `hotend_c`, `bed_c`, and any `hotend_target_c` / `bed_target_c` / `remaining_min` / `layer` / `total_layer` the adapter reports), read live through that printer's own connection, behind the same `X-WebUI-Token` auth as `/api/status`. An unknown id is a 404; an unreachable or `offline`-connection printer answers 200 with `state: "unavailable"` and a detail instead of an error. Built for external consumers such as the Home Assistant integration (ha-print-handy); read-only, it sends nothing to the printer. Offline-tested only. A current-job thumbnail route is not included: no existing machinery produces a per-printer current-job thumbnail, so it stays a follow-up on #664.
- The slot-count setting is renamed: `printer.filament_slots` (environment `PRINT_HANDY__PRINTER__FILAMENT_SLOTS`) is the name now, matching the printer registry and `color_system`, which carries the meaning the old AD5X-specific name implied. Existing installs keep working unchanged: `printer.ifs_slots` in a config file and `PRINT_HANDY__PRINTER__IFS_SLOTS` in the environment still load as a deprecated alias (the new name wins when both are set), and a hardware record written with the old loaded-spool map name is adopted on load. Nothing to change unless you want the new spelling.
- A failed slice now explains the failure and what to do next instead of showing only a generic retry prompt. Process limits use their existing configuration remedy; slicer failures name the engine and exit code, copy placement failures suggest fewer copies, and safety checks stay enforced. Worker errors preserve their category and structured cause, including timeouts. Configuration, guard and engine failures no longer offer an unchanged retry; a transient or unidentified failure still allows one slice-only retry, whose failure keeps its explanation and diagnostics reference. Partial timeout logs are saved before cleanup. The cause of the reported bag-clip failure remains unverified without its runtime logs.
- Printer models name their color architecture (#656, #658): every model in the registry and in code carries `color_system` (`single`, `multi_slot` or `multi_tool`), validated against its slot and tool counts. The Bambu AMS models (A1, A1 mini, A2L, P1P, P1S, P2S, X1, X1C, X1E, H2S) are `multi_slot`, with four slots per AMS (#671, #675); the dual-nozzle H2D family stays `single` on purpose. The Prusa XL is `multi_tool` with five toolheads driven through the adapter contract (#670, #673). Slicing, intake and printing behave as before for every existing model.
- Knowledge coverage for the non-Moonraker families (#647, #668): the Marlin entries name all 21 Marlin models, Prusa Buddy firmware is its own family, and Bambu, SDCP and stock Flashforge carry recorded verdicts in docs/MACROS.md.
- The registries are split by vendor (`printers/registry/`) and by firmware (`firmware/commands/`) (#652, #653). Nothing moved for users; duplicate entries now refuse to load.
- Guided setup asks for the ZMod secrets only on an AD5X (#651).
- Multi-nozzle nozzle change (#676): the guided nozzle-change cooldown checks every extruder, not just the first. It reads each extruder the printer has (from the printer's adapter, else Moonraker's object list) and turns every heater off, not only the active one (#679); before that fix the check only ever saw the first extruder.

**Fixes and reliability (post-2.2.1 review):**
- An upgraded install whose hardware record still names the slot map `ifs_slots` keeps each slot's spool on its first runout or filament pause; the runout recovery and spool lookups, and `spool_lifecycle reconcile --state-file`, adopt the old key like the main loaders do (#677).
- Docker: a container on the shipped default model whose hardware record looks like an AD5X (several loaded slots) logs a warning and shows a `doctor` row naming `PRINT_HANDY__PRINTER__MODEL`; the `filament_slots must be 1` error for `klipper.generic` says the same (#678).
- A slice blocked by a safety guard now says which guard and why in chat (redacted, one line). A Bambu Studio fallback that fails to start keeps the OrcaSlicer failure that triggered it, and a fallback timeout stays retryable (#681).
- `notify.ntfy_enabled` with no topic (neither `ntfy_topic` nor a topic in `ntfy_url`) is refused at load instead of silently skipping every event (#682).
- Contributor tooling: the PR policy check flags an empty `Reason:` line instead of reading the next line as the reason, and the release checklist generator tolerates a PR with no labels (#682).
- Tests: the in-memory clarify gateway that tests/hermes and tests/pipeline install no longer outlives its package, which fixes the order-dependent `/print-stop` routing test hang.
- Direct file link failures now name their cause in chat like the model-site failures do (the #590 known-cause fold for #607/#608, with the remaining Creality Cloud rows from #605): a non-public address, a credential-carrying link, a wrong scheme, a missing host, too many redirects, a web page served instead of the file, or bytes that are not a usable .stl/.3mf are configuration causes with their remedy and no resend advice; a host that cannot be looked up or reached, and an HTTP 429/5xx answer, are transient and may be resent. The HTTP status is read from the curated message (the direct-link error type discards the original HTTP error), so 401/403 classify as configuration just like the site providers. Creality Cloud's download-answer gap and its missing-model answers join the same list; its unexpected answers and bare refusal codes stay honestly unknown. Recognition is by the error type plus the curated phrasing, and the chat wording is built in diagnostics — a link's host or any credentials in it never reach the post. Classification and wording only: no fetch, safety or settings behavior changed.

# Version 2.2.1

**Release Date:** 2026-10-30
**Still owed:** the first live print from chat on a screenless ZMod AD5X (new in 2.2.0); the Sovol profiles, MQTT, exclude-object and the next-plate offer are offline-tested only.

**What users can do now:**
- Pick a Sovol by firmware (#638): Sovol (Klipper) and Sovol (Marlin/OctoPrint) are separate brands, like Flashforge. SV01, SV01 Pro, SV02, SV03, SV04, SV05, SV06 and SV06 Plus are in both; SV06 ACE, SV06 Plus ACE, SV07, SV07 Plus, SV08, SV08 Max, Zero and M1D are Klipper only. Volumes come from OrcaSlicer's 0.4 mm profiles (SV03, SV04 and M1D from Sovol's firmware or single-mode figures); the templates are generic and not checked on hardware. A bare `model: sv06` still means `sovol.sv06`.
- Web UI `/config`: every dropdown is A to Z; one Printer URL field for the selected model's connection (a Moonraker or OctoPrint URL, which may be another computer, or a hostname for Bambu, Prusa, stock Flashforge and Elegoo SDCP), with the other connections' addresses kept on save; an RTSP stream URL (`timelapse.capture_source_url`) for go2rtc; ZMod delivery format shown only for Flashforge ZMod. First-boot setup asks for the same Printer URL and writes the field the model uses.
- Paste a site login token straight into the chat, for every model site that needs one (MakerWorld, Thingiverse, Cults3D, Creality Cloud, Thangs, Nexprint, MyMiniFactory): when a download or lookup needs a missing, empty, expired or refused login, the bot now posts one message with everything in it (why, the numbered steps to get the token, the path for saving it on the Print Handy machine, a plain note on the risk of pasting, and the docs link) and two buttons, **Saved, try again** and **Cancel**, instead of a bare "Connect account" button that hid the steps behind a second prompt. Reply with the token itself, or save the file and reply `saved`. A pasted value is normalized per site (quotes, whitespace, `Bearer`, MyMiniFactory's whole redirect address, Nexprint's `ACCOUNT_INFO` JSON, and for Creality Cloud `model_user_id:model_token` or a cookie string with both cookies in either order), checked for the right shape (ordinary chat and a JWT that has already expired are not saved, and the reply says why without repeating the text), written atomically with owner-only permissions (folder 0700, file 0600), and the download is retried automatically. The bot deletes your message on Discord, Telegram and Matrix when it is allowed to (it says so when it could not), but the chat service may keep a copy, so the note tells you to treat a pasted token like a password. The token is never logged, echoed, or put in a receipt or error text. The refused-then-renew loop is unchanged. Saving the file on the server still works exactly as before. Offline-tested only; not yet run against a live chat.
- Print a model that comes as several files: a Printables link such as the rugged UNO card box (`UNO - container-1.stl`, `UNO - uno-latch-1.stl`, `UNO - cap-sign-1.stl`, `UNO - cap-nosign-1.stl`) used to ask "This model has 4 print profiles. Which profile should I use?" and download only the one picked. On every file-list site (Printables, Thingiverse, MyMiniFactory, Creality Cloud, Thangs, Nexprint, direct links) the files are now parts of one model by default: intake offers all of them as one job, asks one short question per group of versions of one part ("Which cap?" with **sign** / **no sign**), and offers **Choose files** for any subset or a single file. Version groups are found from the file names only (version words, with/without words, `v1`/`v2`, difficulty words, supports, sizes such as `M3`/`M4`); `left`/`right` and numbered parts are always both printed. One 3MF beside STL files is offered first as the whole model. The chosen files are downloaded once each and combined into one geometry-only 3MF with one object per file (`model_parts.combine`, run in the heavy worker), packed onto one bed when they fit; the existing fit, rearrange, split and per-part color steps then handle it. `JOB.json` gains `selected_sources` (every file with its own download) and `combined_objects`; `selected_source` / `downloaded_file` name the combined project, so reprints reuse it. A file already downloaded for an earlier multi-file job is reused instead of fetched again. The intake preview now says "the selected file" for file-list sites; "print profile" stays for MakerWorld. Offline-tested only; not yet checked against a live Printables download.
- Cancel one object from chat (#620): the print-started post lists the plate's labeled objects, and `/exclude <name>` or the object buttons cancel just that one after a confirm (`EXCLUDE_OBJECT` on Klipper). The last remaining object goes to the normal stop confirm instead. A stale button, a different print, or an unreadable printer sends nothing.
- The next plate is offered when the bed is clear (#621): after a plate of a multi-plate plan finishes, the camera checks the bed while the printer is idle, and an empty bed brings back the existing confirm button for the next plate. Nothing starts without that tap.
- Print events over MQTT for Home Assistant (#622): set `notify.mqtt_enabled` and `notify.mqtt_host` (with an optional username; the password is only `MQTT_PASSWORD` in the environment) to publish `print_started`, `paused`, `runout`, `watchdog_offer`, `complete`, `failed` and `spool_added`. Off by default; a broker that is down never delays chat or a print.
- The confirm card says when a color remap made on the printer screen will not reach Spoolman for a `.gcode.3mf` print (#619).
- Printer review shows Moonraker's live nozzle, bed and Z size when adding a Klipper printer.
- Web UI: a read-only sliced-layer view draws each plate's G-code layer by layer (plates up to 8 MB and 200,000 moves).
- Fit options below 100% (live report, AD5X, a 231 x 157 x 135 mm single-body STL): the question described a turned size that fits at 96.3% but offered only "Shrink to 91.6%" and Cancel. The largest sizes that really fit are now buttons, best first (a turn or rotation, a rotation that needs supports only when it is larger than the no-support ones, and a plain shrink only when no turn beats it), and typed "shrink" or a percent resolve to them. The "type ..." hint lists only the actions offered, so it no longer says "split" when there is nothing to split, and the question shows the measured size instead of "measured dimensions unavailable". The tight-fit brim is now chosen only when the part stands on a small contact patch: a wide flat base gets no brim (it used to reserve 3 mm per side), a turned option is sized and sliced with its own brim rule rather than the authored layout's, and the 5 mm small-contact brim is budgeted into that option's size. A rotated single copy is now checked the way it is sliced (bed-centered, no re-arrange), which removes about 1 mm per side of false slack from the check. A single-body model skips the rearrange and split searches, and the convex-hull and vertex passes behind the size search are cheaper, so the check on that model drops from about 49 s to about 15 s. Cutting one oversized body into glued pieces is not built. Offline-tested; the timing and sizes above were measured with the real Orca on a development machine, not on the live bot.

**Fixes and reliability:**
- Fix: pasting an ordinary message, a link or a file path into a site-token prompt no longer saves it as a login token and deletes the message. Links and paths are refused for every site (a MyMiniFactory sign-in address still works for the `access_token=` value inside it), and a Thangs token must be JWT-shaped.
- Fix: a slicer that timed out while the container sat at its process limit reported a bare timeout. The process count is now sampled just before the timeout, while the slicer's threads are still alive, so the limit is named.
- Fix: a multi-file model made of tiny STL files skipped the inch-or-millimeter question, because the combined job is a 3MF. The question is now asked once for the set when the largest STL part is under 10 mm, and an inch answer scales the STL files before they are combined.
- Fix: the Web UI layers page showed only one plate of a multi-plate job, because every plate is named `plate_1.gcode`. Plates are now addressed by position (`/layers/<job>/<n>`), so each one is listed and opens. Old name-style links no longer open.
- Fix: a Moonraker printer's bed size came from the inset bed mesh, which gave false "bed is smaller than this profile" warnings. It now comes from the X and Y stepper travel, with the mesh used only when the steppers are missing. Thread budgets from a CPU quota are also capped at the CPUs the process may run on.
- Fix: fit probes and slices hung for the full Orca timeout when the container sat at its PID limit. A `--cpus` quota does not shrink the CPU count that OrcaSlicer (TBB), numpy, onnxruntime and Python executors see, so on a large host they each started dozens of threads. Pools are now sized to the cgroup CPU quota (or `PRINT_HANDY_THREADS`) and left at their defaults when there is no quota. The shipped Unraid template and Compose file no longer set `--pids-limit`, `--memory` or `--cpus`, and the template gains the optional Account tokens (`/data/.config`) mapping. A refused process start now reports the container PID limit instead of timing out, and the doctor shows process usage against any limit.
- Fix: a restart in the middle of an intake (for example during the fit check) left the chat on "Still checking the fit" forever. On startup the Discord bot now finds intake receipts that another process left in progress (within 24 hours, written by this version), posts one line saying the preparation stopped and nothing was uploaded or started, asks for the link again, and marks the receipt `INTERRUPTED` so it is said once. Nothing is resumed.
- Fix: a stale object-cancel button could exclude an object in a different print. The exclude now reads the printer just before sending and sends nothing unless the same file is still printing or paused. The last-object check now counts objects Klipper already excluded, so the second of two objects goes to the stop confirm instead of being excluded. If the printer cannot be read, nothing is sent.
- Fix: the next-plate offer was said only once per plan, so later plates of the same plan got none. Each finished plate now gets its own offer. The camera bed check also no longer runs while a print is going, and Cancel on an offer stops the checks for that plate.
- Fix: MQTT notifications. `/print-stop` and `/print-resume` no longer publish a false `print_started` event when they only look up the print name. Publishing no longer blocks the bot while a broker is slow. A broker that refuses the connection is now logged, each publish uses its own client id so per-printer listeners stop kicking each other off the broker, and the payload names the printer for per-printer listeners.

## 2. Multi-Plate Capacity Evaluation & Bounding Box Decoupling

### Problem Statement
- In prior versions, `orca_adapter.py:orca_plate_capacity` blindly returned `1` for any multi-plate 3MF file to avoid false negative zero-capacity reports.
- Meanwhile, `verified_scale_choices` evaluated model dimensions by extracting `source_triangles` across the entire 3MF file. In multi-plate Bambu/Orca projects, plates are placed side-by-side in global coordinate space. For the 4-plate Strandbeest, this produced a global bounding box of **501 x 529 mm**, causing `verified_scale_choices` to conclude the model required scaling to `<= 0.41`.

### Implementation Details
- **`_multi_plate_capacity(source, state, scale, single_margin)`**:
  - Inspects `plate_manifest(source)` to extract individual plate object assignments.
  - Uses `color_geometry._world_bounds(archive, object_ids)` to compute the bounding box of each plate independently.
  - Compares each plate's scaled dimensions `(dx, dy, dz)` against usable bed boundaries (`eff_w = bed[0] - 2 * margin`, `eff_d = bed[1] - 2 * margin`, `max_h`).
  - Supports 90-degree bed rotation (`fits = (dx <= eff_w and dy <= eff_d) or (dy <= eff_w and dx <= eff_d)`).
  - Returns `0` if any plate exceeds usable dimensions; returns `1` only if all plates fit.
- **`verified_scale_choices(source, state)`**:
  - Multi-plate 3MF files bypass whole-canvas `source_triangles` extraction.
  - If capacity at 1.0 is `> 0`, returns `[1.0]`.
  - If capacity at 0.5 is `< 1`, returns `[]`.
  - Runs an integer binary search `low, high = 50, 99` over `orca_plate_capacity(..., scale=middle / 100.0)` to find the maximal scale where all plates fit.
  - Returns `_scale_ladder(best_scale)` (for Strandbeest, Plate 3 circular fan at 231 mm yields best scale `0.94`, returning `[0.94, 0.75, 0.5]`).

## 3. Multi-Plate Slicing Isolation & Per-Part Grouping Fix

### Problem Statement
1. In `model_job.py:1668`, `_slice_per_plate` contained:
   ```python
   if fit is not None:
       object_plate = {key: 1 for key in object_plate}
   ```
   If a scale factor was passed to a multi-plate model, all parts across all plates were reassigned to Plate 1 and sliced together onto a single plate.
2. In `model_job.py:per_part_fit_options`, parts were grouped strictly by filament slot:
   ```python
   groups.setdefault(slot, []).append(part['key'])
   ```
   For multi-plate models where multiple parts on different plates share slot 3, this attempted to fit all parts from all plates simultaneously onto one bed during fit testing, triggering `RuntimeError` and yielding empty fit options `{'scales': [], 'rotations': []}`.

### Implementation Details
- **`_slice_per_plate`**:
  - Guard updated to `if fit is not None and len(plates) <= 1:`, preserving plate boundaries when scaling multi-plate projects.

- **`per_part_fit_options`**:
  - Updated grouping to use `(plate_id, slot)` tuples:
    ```python
    p_id = object_plate.get(str(part['object_id']), 1) if plates else 1
    slot = view['choices']['part:' + part['key']]['slot']
    groups.setdefault((p_id, slot) if plates else slot, []).append(part['key'])
    ```
